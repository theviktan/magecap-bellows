# MageCap Bellows 0.5.0

Download `MageCap-Bellows-0.5.0-Windows.zip` below, unzip it anywhere and open `START HERE.txt`.
Everything is included (Python too); you need a graphics driver with Vulkan 1.3.

These notes grow as 0.5.0's work lands; builds until the release report `0.5.0-dev`.

## Keeping things across scenes

- **Keep Across Scenes** (a checkbox in the Inspector's header, or `entity.keep_across_scenes` in
  Python and ForgeScript): the entity and its children stay when `load_scene` changes the scene.
  The player, the music or a game manager keeps its script values (no second `on_create`), its
  physics (it keeps falling or moving) and its playing sounds.
- **Placing it in every level is fine:** when the new scene has the same entity (the same ID), the
  kept one stays and the scene's copy is left out with its children, so there are never two
  players. That holds wherever the scene has its copy, at the top or under a group like "Level".
- **New event `scene loaded`** (name, path), sent to every script after the new scene is in, so a
  kept script can find the new level's things. In ForgeScript: `when scene loaded with name, path`.

## Models that face the other way

- **Front Faces** (right-click a .glb or .gltf in the Content panel): `-Z (as made)` or
  `+Z (turn to face forward)`. Blender and most glTF models are made facing +Z, while Bellows'
  forward is -Z, so they used to face backward. With +Z the model is turned half a turn about its
  up axis when it loads, around its own origin, and every placed copy updates at once.
- The setting is saved beside the model in `<model>.bimport`, so it travels with the model: the
  Content panel renames, moves and deletes it with the model, and doesn't list it. Models
  without one use the project's **Model Front Faces** (Project Settings). **New projects start at
  +Z**, so models from Blender and most stores face forward with no setting. Projects made before
  0.5.0 stay at `-Z`, so nothing already placed turns around.
- Automation: `bellows.editor.model_front(path)` and `set_model_front(path, "+Z")`.

## ForgeScript 1.6.0

ForgeScript reads more like plain English in this release. Every new form below was a mistake
before, so **every 1.5 script runs exactly as it did**. None of the new words are reserved:
`set every to 3`, `set test to 1` and a function called `expect` still work. The Language Guide
covers each one with examples.

**Time and events**
- **Wait for an event:** `wait for door opened`, `wait for hit with damage`, `wait for "Start" is clicked`. A cutscene or a dialog can now say "do this, then wait until that happens" in one place. `wait for scene loaded with name, path` works too, and a kept script's waits carry across `load_scene`.
- **Timers:** `every 3 seconds ... end` and `after 2 seconds ... end`, for spawners, cooldowns and delayed effects. They hold while the game is paused, unless the script is marked Run While Paused.
- **Keeping things across scenes:** `keep self across scenes` (see above).

**Lists and numbers as sentences**
- `sort scores`, `sort enemies by health`, `shuffle deck`, `reverse items`.
- `the length of items`, `first of items`, `the last item of items`, `item 2 of items`.
- `if turn is even then`, `is odd`, `is a whole number`.
- `if every enemy in enemies is defeated then`, `if any score in scores is above 90 then`.
- `for each field, value in goblin do` goes through an object's fields.

**Structure for bigger games**
- **Choices (enums):** `choices State are idle, running, jumping`, then `State.idle`. A typo like `State.idel` is caught before the game runs, and a `match` that forgets a choice gets a warning.
- **Shared values:** `shared count is 0` inside a kind, read and changed as `Enemy.count`.
- **Any number of values:** `function total(numbers...)`.
- **Optional types:** `function heal(amount as number)`. They never change what runs; the editor warns when a call passes a plain value of the wrong type, like `heal("ten")`.

**Editors**
- **Find all uses and rename:** in VS Code or any other editor that runs `forgescript --lsp`, find every use of a variable, function or kind, or rename it everywhere in the script. Two things that only share a name are never mixed up, and when a rename could change what the script does, it says why instead.

**Built-ins for game feel**
- `ease(t, "back out")` and ten other easing curves, smooth `noise(x, y)` for wobble and terrain, `color("#ff8800")` and `hsv(...)` for colors, and `random_chance(0.25)`, `random_direction()` and `random_point_in_circle(5)`. Text gets `capitalize()`, `title()` and `count()`, and lists get `unique()`, `flatten()`, `chunk()`, `max_by()` and `min_by()`.

**Testing and learning**
- **The ForgeScript Cookbook:** thirty ready-to-copy recipes for walking, jumping, health, cooldowns, inventories, loot tables, saving, state machines, quests, pause and main menus, and more. Each one explains how it works, and the recipes that don't need the engine prove their results with tests.
- **Tests in scripts:** `test "armor lowers damage" ... expect damage(10, 3) is 7 ... end`. Tests never run in the game; run them with `forgescript --test Scripts/combat.forge`, which exits with 1 when one fails.
- **Mistakes from other languages teach the ForgeScript:** `x += 1`, `def`, `elif`, `True`, `len(x)`, `list.append(x)` and others now say what to write instead, for example "To add to a value, write: add 1 to x".

## Content panel

- **Delete moves to the Recycle Bin** (Windows) or the Trash (Linux), so an asset deleted by
  mistake can be restored from there. It used to be gone for good.
- **Rename keeps an asset in its folder:** a name with `/`, `\`, `..` or other characters a file
  name can't have is refused, so a rename can't move an asset out of the project.
- **Open in External Editor** opens a script in your text editor. On Windows it used to open the
  file's default program, which for a `.py` file can be Python itself, so it ran the script. When
  Windows has no editor set for the file type, it asks which program to use.

## Upgrading from 0.4

- `load_scene` now loads into the running scene. Without anything marked Keep Across Scenes, games
  behave as before: every entity goes (`on_destroy` runs) and the new scene's entities start.
- `time()` keeps counting across `load_scene`, as the docs always said ("since play started"); it
  used to start again from 0 in each new scene.
