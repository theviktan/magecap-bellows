# MageCap Bellows 0.3.2

Text and game UI arrive: fonts and on-screen text, menus and HUDs built from widgets, themes, and
playing in a game window like Godot's F5. ForgeScript 1.4.0 grows with them, and games can now save
data and report crashes to MageCap Forge.

Download `MageCap-Bellows-0.3.2-Windows.zip` below, unzip it anywhere and open `START HERE.txt`.
Everything is included (Python too); you need a graphics driver with Vulkan 1.3.

The game UI is most of Phase 2 of the plan; the editor's UI tools and Forge's in-game report form
come next, in 0.4.0.

## Text

- **Fonts**: TrueType and OpenType files are assets, drawn sharp at any size (MSDF). Inter is built
  in, and exported games ship it with its license.
- **The Text component** for screen text and world text: size, color, alignment, wrapping, overflow
  (clip or "..."), line spacing, outline, and world labels that turn toward the camera.

## Game UI

- **Canvases and rects**: a UI canvas covers the screen and scales to it (fit height, fit width,
  expand or constant pixels); rects place UI with anchors, a pivot and offsets. UI draws after the
  game, is in screenshots, and can be clicked in the editor.
- **Input the game doesn't also get**: the UI takes the pointer over it, presses, and focus; keys,
  arrows, Tab, Enter and Escape, and gamepad buttons move between widgets (`ui_*` input actions,
  added to older projects when they open). A modal canvas takes everything, for pause menus and
  dialogs. Events (`clicked`, `focused`, `unfocused`, `cancelled`, `changed`, `submitted`) reach the
  widget's scripts and then each parent's.
- **Layout**: vertical, horizontal and grid containers with spacing and padding, scroll areas with
  scroll bars, and 9-slice images.
- **Widgets**: button, toggle, slider, dropdown and text input (typing, selection, the clipboard,
  passwords, several lines). `entity.value`, `text`, `visible`, `interactable` and `focus()` are the
  everyday shortcuts.
- **Themes**: a `.btheme` file restyles every widget on a canvas; the built-in MageCap theme is the
  default, with `primary` and `danger` button styles. Its colors were checked for contrast.
- Every part is in both languages, the Inspector, and **Create > UI** (canvas, panel, text, button,
  toggle, slider, dropdown, text input, vertical layout, scroll list).

## Playing and saving

- **Play in a game window** (F5 the start scene, F6 the open scene, F8 stops): the game runs in its
  own window without the editor, with its log in the Console. Playing in the editor's viewport is
  still there, for the debugger and the live Inspector.
- **Saved data**: `save_data`, `load_data`, `has_data` and `delete_data` keep values in the player's
  folder, safely written; and `real_time()`.
- **Logs**: a game writes `Game.log` in its user folder (`log_folder()`) and keeps the last run's as
  `Game.previous.log`, instead of writing next to the program.

## Errors and crash reports

- A `script error` event reaches every script with the error's message, file, line, call stack,
  language and name, from Python and ForgeScript alike. A `game quitting` event comes just before a
  normal quit. `started_from_editor()` tells a script whether you are playing from the editor.
  MageCap Forge's Forge Link uses them for error and crash reports.

## ForgeScript 1.4.0

Since 0.3.1 (1.2.0), ForgeScript has gained:
- "Did you mean ...?" hints in every unknown-name error (1.3.0).
- `when "Start" is clicked`, and `show`, `hide`, `enable`, `disable` and `focus` for widgets.
- `match`, taking a list apart (`set name, score to entry`), named values in a call
  (`attack(goblin, crit: 5)`), default values (`damage is 10`), `finally`, `"""long text"""`,
  `is between`, and `value if test otherwise other`.
- `format_number`, `format_time`, game math (`move_toward`, `remap`, `smoothstep`, ...), `range`,
  `zip`, JSON, and more list and text helpers.

The full list is in `Docs/ForgeScript/CHANGELOG.md`.

## Fixes

- `.ogg` audio clips load (miniaudio had been built without its Ogg Vorbis decoder).

## Upgrading

Projects from 0.3.0 and 0.3.1 open as they are. Their input actions gain the `ui_*` actions the
first time they open.
